# YookAI v0.3.0-final

## Release scope

This release preserves the v0.3.0-rc1 HTTP/provider/UI contracts and adds isolated capability services:

- `core/agents/loop.py`: bounded AI → tool → result → AI orchestration through injected model, execution, and approval callbacks.
- `core/projects/workspace.py`: project metadata, instructions, files, and confined project-relative file operations.
- `core/context/engine.py`: deterministic token estimation, newest-message budgeting, and extractive compaction summary.
- `core/agents/tasks.py`: persistent task state ledger with terminal-state protection.
- `core/automation/schedule.py`: validated interval schedule metadata, disabled by default.
- `core/mcp/protocol.py`: JSON-RPC request/response primitives for MCP adapters.
- `core/research/fetch.py`: bounded HTTPS fetch with basic public-address and redirect checks.

## Security and integration boundaries

Autonomous model-driven calls are not activated in the default chat endpoint. The loop deliberately accepts injected provider callbacks, so a provider adapter must explicitly map its native tool-call format and apply user consent before connecting it to chat. The local shell remains disabled by default and retains its existing confirmation mechanism. Do not expose the localhost server directly to untrusted networks.

The research module fetches URLs but does not provide a search engine, source-ranking policy, HTML readability extraction, or automatic citations. The MCP module is a protocol helper, not a subprocess/stdio transport or remote-server manager. Task and schedule persistence is provided, but production background execution, retries, locking across processes, and scheduler lifecycle are host-application responsibilities. Semantic memory in this release retains the existing deterministic hashed-vector implementation; it is not a learned embedding model or a dedicated ANN vector database.

These boundaries are explicit so optional capabilities are not represented as fully integrated or silently executed. Use provider-specific integration and deployment review before enabling them in a public or multi-user environment.

## Validation

Run `pytest -q` from the repository root. Release tests cover existing API/provider/UI contracts and the new service-level modules.
