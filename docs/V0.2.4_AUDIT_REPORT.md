# YookAI v0.2.4 — Runtime & Multi-Provider Audit

## Root findings

1. **Retry/repeat action was wired but semantically broken.** `handleRetry()` searched only messages before the clicked row, so clicking retry on the user message could retry the previous turn or do nothing. The retry lifecycle is now target-aware and preserves attachments.
2. **Upload progress could display 100% while the multipart request was still waiting for the server response.** Browser upload progress is now capped at 99%; 100% is emitted only after the upload response succeeds, at which point the spinner is removed.
3. **Provider abstraction was OpenRouter-only at runtime.** The registry now has direct adapters for OpenAI, Anthropic, Google Gemini, and local Ollama while preserving OpenRouter.
4. **Model configuration was global and minimal.** v0.2.4 adds provider/model profiles plus a session snapshot containing temperature, top-p, max tokens, reasoning effort and system prompt.
5. **Stopping a non-default provider could target the wrong provider.** Stop requests now carry the active provider.

## Provider support

- OpenRouter
- OpenAI
- Anthropic
- Google Gemini
- Ollama (local)

Provider adapters normalize streaming into YookAI's SSE contract: reasoning, content, usage, done, error.

## Session model profiles

Profiles are stored in `chat.model_profiles` using `provider:model` keys. Each session stores `model_config` as a snapshot so a historical conversation retains the configuration used for that session.
