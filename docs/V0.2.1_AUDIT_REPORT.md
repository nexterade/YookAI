# YookAI v0.2.1 — Streaming/UI Hotfix Audit

## Findings

### 1. SSE response ownership bug — fixed
`SSEStreamer.close()` closed `BaseHTTPRequestHandler.wfile`. The stdlib HTTP server flushes `wfile` again after request handling, producing `ValueError: I/O operation on closed file`.

**Fix:** SSEStreamer now flushes best-effort and marks itself closed without closing the HTTP handler-owned stream.

### 2. Expected client disconnect noise — contained
`BrokenPipeError` while writing the HTML page can happen when a browser cancels/reloads navigation. The frontend response writer now treats socket disconnects as expected debug-level events instead of an application traceback.

### 3. UTF-8/mojibake — fixed at provider + render boundaries
OpenRouter streaming is explicitly decoded as UTF-8. A conservative mojibake repair routine also repairs already-persisted responses such as `Ã¢ÂÂ` → `—` without rewriting normal text.

### 4. Thinking state — fixed
A thinking block is created immediately when generation starts, so the UI no longer waits for the first reasoning token. It now shows an animated three-dot spinner, a live timer, and transitions to a completed state.

### 5. UI icon glyphs — refactored
Interactive UI icons were converted from legacy Unicode glyphs to inline SVG. Attachment/file indicators remain emoji where appropriate.

### 6. Mobile sidebar backdrop — fixed
The backdrop selector is now scoped to the actual DOM location of the drawer, avoiding a selector mismatch when the backdrop is rendered inside the application shell.

## Screenshot diagnosis

The `BrokenPipeError` shown during `GET /` is a client disconnect, normally caused by navigation/reload/cancellation. It is not evidence of corrupted application state. The later `ValueError: I/O operation on closed file` during `POST /api/chat` is a real YookAI server lifecycle bug caused by closing `wfile` from the SSE helper. That is the bug fixed in this release.
