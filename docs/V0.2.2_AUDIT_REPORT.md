# YookAI v0.2.2 — History, ZIP Attachments & Streaming Latency Audit

## Findings

### 1. Session history appeared empty during generation
The browser created a session only after the provider stream completed. A slow model, a stopped generation, or an upstream error therefore left the chat absent from History.

**Root fix:** persist the session immediately after the user message and assistant placeholder are created. The same session is updated again after completion/stop/error.

### 2. ZIP attachments were stored but not document-readable
The attachment layer already supported several document formats, but `.zip` was treated as opaque binary.

**Root fix:** ZIP is now processed in memory with hard bounds: 200 files, 40 MB total uncompressed content, 10 MB per member. No archive member is extracted to disk, so archive path traversal cannot write outside the attachment directory. Supported text/document members are concatenated into a bounded context; unsupported binary members are reported rather than executed.

### 3. Streaming latency had avoidable client-side buffering
`requests.Response.iter_lines()` was using its default buffering behavior. Small SSE events could wait for a larger network chunk before reaching YookAI's frontend. The provider also advertised `application/json` instead of the more precise `text/event-stream` accept type.

**Root fix:** use `iter_lines(chunk_size=1, decode_unicode=True)` and `Accept: text/event-stream`. This does not remove model/provider latency, but reduces YookAI-side waiting between upstream SSE events and the UI.

### 4. Server timing was opaque
The server log previously did not distinguish connection latency, time-to-first-upstream-event, and total generation time.

**Root fix:** OpenRouter logs now record model, request id, upstream connection time, first event time, and total stream time without logging API keys or prompt contents.

## About localhost speed

`localhost` is normally not the dominant latency source because the browser-to-YookAI hop is local. The larger contributors are typically: model queue/inference time, upstream network/TLS latency, reasoning duration, and provider-side buffering. YookAI's new timing fields make these components easier to diagnose.
