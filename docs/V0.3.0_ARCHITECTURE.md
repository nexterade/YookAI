# YookAI v0.3.x Architecture

v0.3.x is a structural evolution, not a destructive rewrite. The existing v0.2.4
HTTP/API and provider contracts remain compatible while new domain boundaries are
introduced incrementally.

## Layers

- `app/`: HTTP transport, routing, SSE and request handling.
- `core/`: domain services and stable application boundaries.
- `providers/`: external/local AI provider adapters.
- `templates/`: browser UI.
- `tools/`: operator and maintenance commands.
- `tests/`: unit, provider, API and end-to-end suites.
- `static/`: future static assets (SVG icons, fonts, images).

## Runtime isolation

Source code stays in the project directory. Mutable state lives below
`~/.yookai/`: configuration, sessions, memory, attachments, cache and logs.

## Compatibility rule

During v0.3.x, move one capability at a time. Existing imports are preserved with
facade modules so every refactor can be tested independently.

## Planned capability domains

1. Chat orchestration and context budgeting.
2. Session/history/search.
3. Attachment extraction and archive processing.
4. Model catalog, capabilities and per-model profiles.
5. Provider health, latency routing and fallback.
6. Local tools with explicit confirmation boundaries.
7. Diagnostics, migrations and observability.
