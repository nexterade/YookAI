# YookAI v0.2.3 — Startup, Latency Selection & Attachment Upload Audit

## Changes

### Interactive pre-listen configuration
`python3 server.py` now opens a terminal configuration menu before the HTTP server starts listening when stdin is interactive.

Options include:
- OpenRouter API key
- model strategy
- memory mode
- host/port
- theme
- immediate latency benchmark
- save/start or quit

Flags:
- `--no-configure` skips the menu
- `--configure` forces the menu

### Latency-based default model
The previous hard-coded `deepseek/deepseek-r1` default is migrated to `latency-best-free` when an existing configuration does not yet define a model strategy.

The benchmark:
- uses OpenRouter's live model list
- tests free chat models only
- sends a bounded 1-token streaming probe
- measures time-to-first-SSE-event (TTFT)
- tests at most five candidates per run
- uses a short `(4s connect, 8s read)` timeout
- caches the result for six hours
- persists the fastest successful model as `chat.default_model`

This measures the actual route from the user's device through OpenRouter, so it is more useful than a static model ranking for this purpose. It does not rank response quality.

### Attachment upload animation
Uploads now use XMLHttpRequest because it exposes upload progress. The UI shows:
- spinner
- filename
- percentage
- progress bar
- disabled send action while any upload is active

The existing 20 MB/file server-side limit remains authoritative.

## Latency interpretation
The v0.2.2 logs supplied during development showed approximately:
- upstream connection: 1256 ms
- first SSE event: 1936 ms
- total stream: 1939 ms

That means the local HTTP hop is not the dominant component in that sample. The benchmark in v0.2.3 makes the same measurement per candidate model and selects the lowest TTFT among successful free candidates.

A very large thinking timer with no output can still be caused by model/provider inference or upstream queueing; the local server cannot remove that upstream delay.
